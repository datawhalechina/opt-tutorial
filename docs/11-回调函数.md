# 第 11 章 回调函数：在求解过程中拿到内部信息

第 6 章讲的是"事后读日志"——求解器愿意告诉你的东西，都在日志里。回调（callback）是另一回事：求解器在求解**过程中**停下来叫你的函数，你可以读它的内部状态，甚至改它的求解过程。

这一章只回答三个问题：

1. MIP 求解时根节点的 LP 松弛解长什么样？
2. 这个松弛给出的界有多松？
3. 能不能在求解中途干预（加割、给解、提前终止）？

同一道题（第 7 章的 CVRP，MTZ 写法）在五家求解器上各跑一遍。结论先放在这里：

- **只想看根松弛解和界，90% 的场景不需要回调**（11.5），单独建一个 LP 松弛模型解一次就行，五家通用，改动只是把整数变量换成连续变量。
- **五家的回调能力差得很远**（11.3）：Gurobi / COPT 能取节点 LP 解、能加懒约束；HiGHS 1.16 只能拿解和界；SCIP 是"事件处理器"不是回调。
- **真需要回调的场景是干预**（11.6）：本章用懒约束把一道"求解器报告最优、但答案其实是错的"的模型改对。

## 11.1 回调能干什么

| 用途 | 典型需求 | 需要的能力 |
| :--- | :--- | :--- |
| 诊断 | 根松弛解、根界、哪些 0-1 变量卡在小数 | 读节点 LP 松弛解（或单独解 LP） |
| 干预 | 懒约束（子回路消除）、用户割、给一个 MIP start、提前终止 | 回调里能加割 / 能停 |
| 监控 | 界收敛曲线、每找到一个新解就记一笔 | 解/界更新事件 |

三个用途里，**诊断的需求最普遍，但对回调的依赖最小**。原因很直白：根松弛解就是"把整数约束去掉之后的最优解"，你完全可以自己建一个 LP 模型去解，不必求求解器在它自己的回调里告诉你。

真正非回调不可的是干预：只有处在求解过程内部，你才能在"刚发现一个整数解"的那一瞬间检查它、并塞回一条新约束。

## 11.2 根松弛 vs 整数最优：界到底有多松

本章的模型是第 7 章的 CVRP：1 个配送中心（0 号点）+ 5 个客户，车辆载重 15，目标是最小化总行驶距离。约束是标准的四组：

- 每个客户出度 = 1、入度 = 1（`out_i` / `in_j`）
- 载重区间（`load_lb` / `load_ub`）
- MTZ 子回路消除（`mtz_i_j`，大 M 取车辆载重 15）
- 配送中心进出平衡（`depot_balance`）

整数最优是 **141.84**（`common/data.py` 里的标准答案）。把 `x` 从 0-1 变量换成 $[0,1]$ 连续变量、其余一条不改，解一次 LP，得到 **114.153**。

同一套写法跑本仓库其它两个模型，对比一下"松"的差别：

> 实测对照（根 LP 松弛界 vs 整数最优，用与本章相同的 LP 松弛写法算出）：

| 模型 | 根 LP 松弛界 | 整数最优 | 根节点 Gap | LP 解的样子 |
| :--- | ---: | ---: | ---: | :--- |
| 第 2 章 0-1 背包（4 件） | 15.000 | 15.000 | 0.00% | LP 解恰好全是整数 |
| 第 3 章 设施选址（3×4） | 220.222 | 273.000 | 19.33% | 三个仓各开 0.222 / 0.333 / 0.444 |
| 第 7 章 CVRP（MTZ） | 114.153 | 141.840 | 19.52% | 12 条弧取 1/3 或 2/3 |

背包那一行值得单独说：它的 LP 松弛解恰好是整数（$x=(1,1,0,1)$，重量正好 $2+3+5=10$），所以 Gap 是 0。这不是"背包容易"，而是这道 4 件题的系数凑巧——用它当例子，你会误以为 MIP 的松弛界总是很紧。

CVRP 的 LP 解才是常态：30 条弧里有 12 条是分数，取值不是 $1/3$ 就是 $2/3$：

```
x0_5 = 0.3333    x1_3 = 0.6667    x1_5 = 0.3333    x2_4 = 0.6667
x2_5 = 0.3333    x3_1 = 0.6667    x3_4 = 0.3333    x4_2 = 0.6667
x4_3 = 0.3333    x5_0 = 0.3333    x5_1 = 0.3333    x5_2 = 0.3333
```

度数约束 `sum_j x_ij = 1` 被 $0.6667 + 0.3333 = 1$ 满足，但"一辆车 2/3 走这条弧、1/3 走那条弧"在现实里不存在。**LP 允许车被切开用**，这就是 MIP 难的根源：松弛解合法、整数解才合法，两者之间隔着一整棵分支树。

根节点 Gap 的计算口径同第 6 章（最小化问题）：

$$
\text{Gap} = \frac{\text{整数最优} - \text{根松弛界}}{|\text{整数最优}|} = \frac{141.84 - 114.153}{141.84} = 19.52\%
$$

补一个数：同一道题 SCIP 的根节点对偶界是 **134.595**（加了一批割平面之后），最终最优 141.84。也就是说根松弛的 114.15 里，有 20.4 是割平面补回来的，剩下 7.2 靠分支。

## 11.3 五家回调能力对照

| 能力 | Gurobi 14 | COPT 8.0.1 | HiGHS 1.16 | SCIP（PySCIPOpt 6.3） |
| :--- | :--- | :--- | :--- | :--- |
| 注册方式 | `optimize(callback=fn)` | `setCallback(cb对象, 位掩码)` | `h.cbMipSolution += fn` | `includeEventhdlr(eh,…)` + `catchEvent` |
| 回调形态 | `fn(model, where)` | 继承 `CallbackBase`，覆写 `callback(self)` | `fn(event)`，event 是 `HighsCallbackEvent` | 继承 `Eventhdlr`，覆写 `eventexec(self, event)` |
| 节点 LP 松弛解 | `cbGetNodeRel(vars)` | `getRelaxSol()`（返回 **list**） | ✗ 没有节点 LP 事件 | `getSolVal(None, var)` |
| 松弛目标值 | `cbGet(MIPNODE_OBJBND)` | `getInfo(CbInfo.RelaxSolObj)` | ✗ 只有 `mip_dual_bound` | `getLPObjVal()`（**缩放后**） |
| 整数解 | `cbGetSolution(vars)` | `getSolution()` | `event.data_out.mip_solution` / `e.val(var)` | `model.getBestSol()` + `getSolVal` |
| 加懒约束 | `cbLazy(lhs, sense, rhs)` | `addLazyConstr(约束)` | ⚠️ 有 `MipDefineLazyConstraints` 回调类型，但 Python 绑定只给读割池（`event.cuts`），**没有加割接口** | ✗ 要写 conshdlr 插件 |
| 加用户割 | `cbCut(lhs, sense, rhs)`（仅 MIPNODE） | `addUserCut(约束)` | ✗ | ✗ 要写 separator 插件 |
| 喂解 | `cbSetSolution` / `cbUseSolution` | `setSolution(...)` | `data_in.setSolution` | `model.trySol(sol)` |
| 提前终止 | `model.terminate()` | `self.interrupt()` | `e.interrupt()` | `model.interruptSolve()` |
| 本章是否实跑 | ✗ 无 license | ✓ | ✓ | ✓ |

三句话记住差异：

- **Gurobi / COPT** 是"真回调"：给你节点级 LP、能加割、能塞解。
- **HiGHS 1.16** 是"通知式回调"：只在有新解/新日志时叫你，`HighsCallbackInput` 里只有 `setSolution` / `user_solution` / `repairSolution` / `user_interrupt` 四个可用入口，**没有加割的地方**，也**没有节点 LP 事件**。

  > 细节：1.16 的回调类型里确实有一个 `MipDefineLazyConstraints`（`h.cbMipDefineLazyConstraints`），看着像"能加懒约束"，但 Python 这一层只提供**读**割池的能力（`event.cut(i)` / `event.cuts`），没有把新约束塞回去的接口。所以写模型时仍按"HiGHS 不支持懒约束"处理。
- **SCIP** 是事件总线：`FIRSTLPSOLVED`、`LPSOLVED`、`NODEFOCUSED`、`BESTSOLFOUND`……你得自己订阅、自己拼出"求解进行到哪了"。

## 11.4 逐家写法与实测

### 11.4.1 COPT：能拿到根松弛解，但要看模型

COPT 的回调对象必须继承 `coptpy.CallbackBase`，注册时给一个**位掩码**（可以同时订阅多个上下文）：

```python
class RootCallback(cp.CallbackBase):
    def callback(self):
        where = self.where()            # 是方法，不是属性！
        if where == COPT.CBCONTEXT_MIPRELAX:
            bound = self.getInfo(COPT.CbInfo.RelaxSolObj)   # 松弛目标值
            values = self.getRelaxSol()                     # 返回 list，按变量创建顺序
        elif where == COPT.CBCONTEXT.MIPSOL:
            sol = self.getSolution()                        # 整数解，同样是 list

cb = RootCallback()
model.setCallback(cb, COPT.CBCONTEXT_MIPRELAX | COPT.CBCONTEXT_MIPSOL
                     | COPT.CBCONTEXT_MIPNODE | COPT.CBCONTEXT_INCUMBENT)
```

`code/ch11_callback/rootrelax_copt.py` 的真实输出：

```
[COPT] 根 LP 松弛界        = 114.153
[COPT] LP 解里的分数弧     = 12 条
        x0_5 = 0.3333
        x1_3 = 0.6667
        ...
[COPT] 回调触发次数        = {'MIPSOL': 29, 'INCUMBENT': 4, 'MIPRELAX': 84, 'MIPNODE': 24}
[COPT] 回调拿到的松弛界    = 114.15333333333334
[COPT] 用回调松弛解自算目标 = 114.153
[COPT] 第一个 MIPSOL 解目标 = 161.64（按解自己算）
[COPT] 回调里被兜住的异常   = 0 次
[COPT] 整数最优            = 141.84
[COPT] 根节点 Gap           = 19.52%
```

四个观察：

1. **回调给的松弛解就是 LP 松弛解**：`RelaxSolObj` 114.1533 与单独解 LP 的 114.153 一致，把回调给的 35 个变量值（30 个 `x` + 5 个 `u`）按目标函数重算，也是 114.153。
2. **`getRelaxSol()` 返回的是普通 Python list**，不是 MVar——想按变量名取，得自己 `dict(zip(vars, values))`。
3. **`MIPSOL` 里的 `BestObj` 不是这个解的目标值**。它返回 `1e+30`（还没更新），所以上面那行"第一个 MIPSOL 解目标"是按解向量自己算的。而且这个数每次运行会变（161.64 / 202.42 都出现过）——多线程下先被哪个启发式找到解，本来就不保证顺序。
4. **`MIPRELAX` 触发 84 次**：第一次给的是根松弛 114.153，后面几次的值更高（我抓到过 115.83），是加割之后重解的松弛。

但 **`MIPRELAX` 不保证触发**。同一个回调类，换模型跑：

> 实测对照（同一个 `RootCallback` 类，四个上下文全注册）：

| 模型 | 规模 | `MIPRELAX` 触发次数 | 能否拿到根松弛 |
| :--- | :--- | ---: | :--- |
| 第 2 章 0-1 背包 | 4 个 0-1 变量、1 条约束 | **0** | 拿不到 |
| 第 3 章 设施选址 | 3+12 变量、3 仓 4 客户 | **2** | 拿得到，第一次 220.222 |
| 第 7 章 CVRP（本章） | 35 变量、41 条约束 | **84** | 拿得到，第一次 114.153 |

原因不难理解：小模型在预处理阶段/根节点启发式里就被解掉了，求解器根本没"显式解一次根节点 LP"，自然不会给你 `MIPRELAX`。所以**不能把"取根松弛界"这件事建在回调上**——这就是 11.5 要说的。

另外 `MIPNODE` 上下文（每个分支节点）也能取节点松弛解，我单独注册它跑 CVRP 时，前三个节点分别给出 137.617 / 138.190 / 138.330——都高于根松弛 114.153，符合"往下走界越来越紧"。

### 11.4.2 HiGHS：1.16 的回调只给解和界，拿不到节点 LP

HiGHS 1.16 的写法是**订阅事件**，不是 `setCallback(fn, data)`：

```python
def on_solution(event):                      # event 是 HighsCallbackEvent
    print(event.message, event.data_out.mip_primal_bound,
          event.data_out.mip_dual_bound, event.data_out.mip_node_count)
    print(event.val(x[0, 1]))                # 按变量取当前解

h = highspy.Highs()
h.cbMipSolution += on_solution               # 3 = MipSolution
h.cbMipImprovingSolution += on_solution      # 4 = MipImprovingSolution
h.cbMipLogging += on_solution                # 5 = MipLogging（output_flag=False 时不触发）
h.run()
```

`code/ch11_callback/rootrelax_highs.py` 的真实输出：

```
[HiGHS] 根 LP 松弛界       = 114.153
[HiGHS] LP 解里的分数弧    = 12 条
[HiGHS] 旧写法 setCallback 触发 = 0 次（结果是 141.84）
[HiGHS] 新写法 cbMipSolution 等触发 = {'MipSolution': 1, 'MipImprovingSolution': 1}
[HiGHS] 第一条 MIP 回调: 解=141.84 上界=inf 下界=-inf 节点=0
[HiGHS] 整数最优           = 141.84（搜索节点 5 个）
[HiGHS] 根节点 Gap          = 19.52%
```

结论很硬：

- **`setCallback(fn, data)` 的五参签名在 1.16 里不触发任何回调**（实测 0 次）。它在 `Highs.setCallback.__doc__` 里还写着 `Callable[[int, str, HighsCallbackOutput, HighsCallbackInput, object], None]`，但 `Highs.__init__` 已经把这个位置占给了内部的转发器；单独用它注册，解完了也不会被调用。要用 `h.cbXxx += fn`。
- **回调里拿不到节点 LP 松弛解**。回调类型只有 Logging / SimplexInterrupt / IpmInterrupt / MipSolution / MipImprovingSolution / MipLogging / MipInterrupt / MipGetCutPool / MipDefineLazyConstraints / MipUserSolution 十种，没有"节点 LP"这一类，`HighsCallbackOutput` 里也没有 `relax_solution` 字段。
- 第一次 `MipSolution` 事件时，`mip_dual_bound` 还是 `-inf`、`mip_primal_bound` 是 `inf`（那一刻界还没写进这两个字段），所以**连"当时的界"都指望不上**。

> 还有一个更危险的：在回调里调 `h.addConstr(...)` 不报错，会把求解搞成 `kSolveError`。实测：在 `MipSolution` 里加一条 `sum(x) <= 5`，`addConstr` 返回正常、`getConstrs()` 也真的多了一条，但 `run()` 结束后 `getModelStatus()` 变成 `kSolveError`、目标值 0。**HiGHS 回调里不要改模型。**

### 11.4.3 SCIP：事件处理器，注意目标值被缩放过

SCIP 没有"回调函数"，只有事件处理器。注册分两步：`eventinit` 里订阅，`eventexec` 里处理。

```python
class NodeWatcher(Eventhdlr):
    def eventinit(self):
        for event_type in (SCIP_EVENTTYPE.FIRSTLPSOLVED, SCIP_EVENTTYPE.NODEFOCUSED,
                           SCIP_EVENTTYPE.BESTSOLFOUND):
            self.model.catchEvent(event_type, self)

    def eventexec(self, event):
        if self.model.getStage() != SCIP_STAGE.SOLVING:   # 预处理阶段读 LP 会报错/崩溃
            return
        values = {a: self.model.getSolVal(None, self.x[a]) for a in self.arcs}  # 当前 LP 解
        ...

model.includeEventhdlr(NodeWatcher(...), "NodeWatcher", "记录根 LP 与新解事件")
```

`code/ch11_callback/rootrelax_scip.py` 的真实输出：

```
[SCIP] 根 LP 松弛界        = 114.153
[SCIP] LP 解里的分数弧     = 12 条
[SCIP] 事件触发次数        = {'NODEFOCUSED': 10, 'BESTSOLFOUND': 2, 'FIRSTLPSOLVED': 10,
                              'LPSOLVED': 16, 'NODEBRANCHED': 4, 'NODEINFEASIBLE': 5}
[SCIP] 回调里的 LP 目标值   = 11415.3（缩放后）
[SCIP] 按 LP 解自己算       = 114.153（缩放因子 100）
[SCIP] 那个 LP 解的分数弧   = 12 条
[SCIP] 前几个事件           =
        NODEFOCUSED   depth=0 lp=0 dual=-1e+20 primal=1e+20
        BESTSOLFOUND  depth=0 lp=15661 dual=0 primal=1e+20
        FIRSTLPSOLVED depth=0 lp=11415.3 dual=0 primal=156.61
        BESTSOLFOUND  depth=0 lp=11415.3 dual=114.153 primal=156.61
[SCIP] 整数最优            = 141.84（搜索节点 9 个）
[SCIP] 根节点 Gap           = 19.52%
```

三个观察：

1. **`getLPObjVal()` 返回的是缩放后的目标值**：11415.3，正好是真值 114.153 的 100 倍。SCIP 会按目标系数的小数位把目标放大成整数（这里的距离是两位小数 → 放大 100 倍）。想拿正常量纲，用 `getDualbound()`，或者像本例一样用 `getSolVal(None, var)` 取 LP 解、自己按模型算目标值。
2. **`FIRSTLPSOLVED` 是"每个节点的第一个 LP 解"**，不是"整场求解的第一次"：本次节点数 9、触发 10 次（根节点也各算一次）。
3. **订阅 `NODESOLVED` 实际收到的是它的子事件** `NODEBRANCHED`（4 次）和 `NODEINFEASIBLE`（5 次），事件名要自己映射，否则打印出来是一串整数编号。

还有一条要命的：**在预处理阶段读 LP 会出事**。`FIRSTLPSOLVED` 在小模型上（例如第 2 章的背包）会在预处理阶段就触发，此时 `getLPObjVal()` 打出

```
[debug.c:2489] ERROR: cannot call method <SCIPgetLPObjval> in presolving stage
```

而在 CVRP 上不加判断地连 `getLPObjVal` + `getSolVal` + `getDualbound` 一起读，我这边直接段错误（退出码 139，没有任何 Python traceback）。先判 `getStage() == SCIP_STAGE.SOLVING` 再读，是必须的。

### 11.4.4 Gurobi：代码写好了，但没 license 没跑

⚠️ 本机 Gurobi 许可证已过期（`GurobiError: License expired 2025-07-02`），连 `gp.Model()` 都建不出来，所以 `rootrelax_gurobi.py` 和 `lazycuts_gurobi.py` **只做了 API 核对，没有实际运行**。签名是通过 `inspect` / `__doc__` 核对的：

> 实测对照（gurobipy 14.0.0，`inspect.signature` 与官方 docstring）：

| API | 核对结果 |
| :--- | :--- |
| `gp.Model.optimize` | `(self, callback=None, wheres=None)` |
| `gp.Model.cbGetNodeRel` | 文档：仅当 `where == GRB.Callback.MIPNODE` 且 `MIPNODE_STATUS == GRB.OPTIMAL` 时可用 |
| `cbGetNodeRel` 的参数 | 文档明确接受"变量、矩阵变量、变量列表、变量字典"——**单个变量也合法**，返回标量 |
| `gp.Model.cbGetSolution` | 仅 `MIPSOL` / `MULTIOBJ` 可用 |
| `gp.Model.cbLazy` | `(self, lhs, sense=None, rhs=None)`，仅 `MIPNODE` / `MIPSOL` 可用 |
| `gp.Model.cbCut` | 仅 `MIPNODE` 可用；文档建议配 `Params.PreCrush = 1` |
| `GRB.Param.LazyConstraints` / `PreCrush` | 均存在 |

写法上和 COPT 的差别只有"注册"：

```python
def mycb(model, where):
    if where == GRB.Callback.MIPNODE:
        if model.cbGet(GRB.Callback.MIPNODE_STATUS) != GRB.OPTIMAL:
            return                          # 节点 LP 没解到最优，取不到松弛解
        bound = model.cbGet(GRB.Callback.MIPNODE_OBJBND)
        relax = model.cbGetNodeRel(x)        # 传变量容器；单个变量也行
    elif where == GRB.Callback.MIPSOL:
        sol = model.cbGetSolution(x)

model.optimize(callback=mycb)                # 也可以 optimize(callback=mycb, wheres=[...])
```

> 关于"`cbGetNodeRel` 只能传变量列表"这个流传很广的说法：官方 docstring 明确写着单个变量、列表、字典、MVar 都接受，返回格式跟着输入变。真正会报错的是**不传参数**，以及**在 `MIPNODE` 之外调用**。

### 11.4.5 CPLEX：这一章为什么没有例子

docplex 2.32.264 有 `Model.register_callback(cb_type)`，但它只是把活转给引擎：

```python
def register_callback(self, cb_type):
    cplex_cb = self.__engine.register_callback(cb_type)   # 需要 CPLEX 运行时
    ...
```

没有 CPLEX 运行时的时候，它**不报错、静默返回 `None`**：

```python
m = Model("t"); m.maximize(m.binary_var("x"))
print(m.register_callback(MyCallback))     # None —— 回调其实没挂上
m.solve()                                  # DOcplexException: Cannot solve model: no CPLEX runtime found.
```

真要用回调得走 `cplex` 模块（`cplex.Cplex().solve(ur_callback=...)`），而本机 `import cplex` 直接 `ModuleNotFoundError`。**一个"注册成功"却静默无效的回调接口，比没有更坑**，所以本章不给 CPLEX 的例子——要抄就抄 11.4.1 或 11.4.4。

## 11.5 可移植替代：单独解一次 LP 松弛（90% 场景的正确做法）

回到最初的问题"根松弛解是什么、界有多松"。这件事**不需要任何回调**：

```python
# 和整数模型共用同一份约束，只把 0-1 变量换成 [0,1] 连续变量
x = {(i, j): model.addVar(lb=0, ub=1, vtype=COPT.CONTINUOUS, name=f"x{i}_{j}") ...}
model.solve()
print(model.objval)          # 114.153 —— 根松弛界
print(x[1, 3].x)             # 0.6667 —— 哪个变量卡在小数，一目了然
```

三个好处：

- **五家通用**：这段代码换掉建模 API 就能在 Gurobi / COPT / HiGHS / SCIP / CPLEX 上跑，本章 11.4 里三家实跑的 114.153 完全一致。
- **成本极低**：一次 LP 求解，毫秒级；不用赌 `MIPRELAX` 会不会触发。
- **信息更全**：回调只给你"当下这一个"松弛解；单独解 LP 时你可以随便折腾——固定某个变量看界怎么变、加一条割再解、把分数解画成图。

它的局限也要说清楚：**它给的是"根节点、未加任何割"的松弛**，不是求解器在第 7 个节点上的松弛。需要后者才用回调。

| 你想知道 | 该用什么 |
| :--- | :--- |
| 根 LP 松弛界 / 分数解长什么样 | 单独解 LP 松弛（本节） |
| 根节点加割后的界 | 单独解 LP + 手工加那批割；或让 MIP 跑到 `TimeLimit` 看 `BestBound` |
| 某个中间节点的松弛解 | 回调（Gurobi `MIPNODE` / COPT `MIPNODE`） |
| 界收敛曲线 | 第 6 章的日志；或 `MIPSOL` 回调里记 `(时间, 界, 解)` |
| 中途加约束 / 提前终止 | 回调（下一节） |

## 11.6 干预：懒约束能把"错误的正确答案"改对

懒约束（lazy constraint）是"回调不可替代"的典型场景：模型里只写一部分约束，剩下的等求解器找到一个整数解、你检查完再补。

用 6 点 TSP 演示（把 CVRP 的载重去掉，就是 TSP；坐标沿用 `common.data.CVRP`）。模型里**故意只写出入度约束，不写子回路消除**：

```
[COPT] 不写子回路消除：
        求解器报告最优 = 110.8
        但这个'解'其实是 3 条回路：[[0, 5], [1, 3], [2, 4]]
[COPT] 用懒约束补子回路消除：
        求解器报告最优 = 119.48
        回路 = [[0, 5, 2, 4, 3, 1]]
        回调里一共加了 5 条懒约束（割的顺序随求解器给的解而变，这里省掉）
[COPT] 暴力枚举（120 条回路）= 119.48
```

第一段是本章最该记住的一段输出：**求解器会说"最优 110.8"，状态是 `optimal`，但那个"最优解"是三条互不相连的回路**（0→5→0、1→3→1、2→4→2）。它对你的模型而言完全非法，只是你没把禁止它的约束写进模型。这类错误不会报错、不会警告，只会给你一个看起来很正常的数——第 9 章说的"两家的解对不上，先查模型"就是这个道理。

第二段是修法。回调在 `MIPSOL` 里取整数解，把选中的弧还原成回路，发现哪条回路不经过 0 号点，就补一条子回路消除：

```python
class SubtourCutter(cp.CallbackBase):          # __init__ 里存下变量表 x
    def callback(self):
        if self.where() != COPT.CBCONTEXT_MIPSOL:
            return
        values = dict(zip(self.x, self.getSolution()))
        for cycle in find_cycles(values):          # 沿着被选中的弧走一圈，还原成回路
            if 0 not in cycle:                     # 没经过配送中心 = 子回路
                self.addLazyConstr(
                    cp.quicksum(self.x[i, j] for i in cycle for j in cycle if i != j)
                    <= len(cycle) - 1
                )

model.setCallback(SubtourCutter(x), COPT.CBCONTEXT_MIPSOL)
```

Gurobi 版逻辑一模一样，只是三处 API 不同（`code/ch11_callback/lazycuts_gurobi.py`，未实跑）：

| 动作 | COPT | Gurobi |
| :--- | :--- | :--- |
| 打开懒约束 | 不需要开关 | `model.Params.LazyConstraints = 1`（**忘了就静默失效**） |
| 取当前整数解 | `self.getSolution()` | `model.cbGetSolution(vars)` |
| 加懒约束 | `self.addLazyConstr(约束)` | `model.cbLazy(lhs, GRB.LESS_EQUAL, rhs)` |

两条纪律：

1. **懒约束只允许砍掉"按原模型本来就不合法"的解**。砍错了，求解器会给你一个错误的"最优"——而且照样报告 `optimal`。
2. **懒约束会拖慢求解**：每个整数解都要过一遍你的分离逻辑。分离逻辑写得太重（比如每步都做一次全枚举），求解时间会被回调吃掉。

## 11.7 坑

1. **COPT 回调里抛异常 = 进程直接死**，没有 traceback：

   ```
   libc++abi: terminating due to uncaught exception of type Swig::DirectorMethodException
   ```

   实测：回调里 `raise RuntimeError` 一条就够。所以回调体要么简单到不会抛，要么自己 `try/except` 兜住（本章的 `rootrelax_copt.py` 是后者，并统计兜住了几次）。

2. **COPT 的 `where` 是方法**：`self.where()`，漏了括号会把绑定方法拿去和整数常量比，永远不相等，回调看起来"一次都没触发"。

3. **COPT 不同 context 能取的 info 不同**。在 `MIPSOL` 里取 `RelaxSolObj` 会打

   ```
   [Error] (INVALID) Fail to get double info in callback
   ```

   并抛 `CoptError`；取 `Incumbent` 抛 `ValueError: Unsupported callback information`。按上下文取对应的量：`MIPRELAX`/`MIPNODE` 取松弛，`MIPSOL`/`INCUMBENT` 取解。

4. **COPT 的 `MIPRELAX` 可能一次都不触发**（见 11.4.1 的表）。凡是"只在回调里才拿得到的信息"，都要有回退路径。

5. **HiGHS 1.16 别用 `setCallback(fn, data)` 注册**：五参签名还在，但不触发。用 `h.cbMipSolution += fn` 这类订阅。

6. **HiGHS 回调里不要改模型**：`addConstr` 不报错，但求解会变成 `kSolveError`。

7. **HiGHS 的回调类型常量没在顶层导出**，`highspy.HighsCallbackType` 不存在，要从 `highspy._core.cb.HighsCallbackType` 拿；`event.callback_type` 只是个整数（3 = MipSolution，4 = MipImprovingSolution，5 = MipLogging）。

8. **SCIP 预处理阶段读 LP 会报错甚至段错误**：先判 `getStage() == SCIP_STAGE.SOLVING`。

9. **SCIP 的 `getLPObjVal()` 是缩放后的目标值**（本例 ×100，倍数取决于目标系数的小数位）。要正常量纲就用 `getDualbound()`，或者按 LP 解自己算。

10. **SCIP 订阅 `NODESOLVED` 收到的是子事件**（`NODEBRANCHED` / `NODEINFEASIBLE`），别按父事件名硬匹配。

11. **Gurobi 的 `cbGetNodeRel` 只能在 `MIPNODE` + `OPTIMAL` 时调**；`cbCut` 只能在 `MIPNODE`，`cbLazy` 在 `MIPNODE` 或 `MIPSOL`。"只能传变量列表"是误传——单个变量也合法。

12. **加了用户割记得 `Params.PreCrush = 1`**：预处理里的某些化简会让你的割作用不到 presolved 模型上，结果是割被静默忽略——官方文档原话是 *your cut being silently ignored*。

13. **多线程下回调的调用顺序不保证**。同一份 COPT 脚本跑三次，触发次数都是 `{MIPSOL: 29, INCUMBENT: 4, MIPRELAX: 84, MIPNODE: 24}`，但"第一个 MIPSOL 解的目标值"在 161.64 和 202.42 之间跳。回调里**不要依赖"第一次调用一定是某某"**，除非像本章这样明确只取根松弛。

14. **回调里别做重活、别打印太多**。`MIPSOL` 每次调用都插在你自己的求解循环里，一行 `print` 乘以几百次就是肉眼可见的变慢。要记录就存列表，解完统一打印。
