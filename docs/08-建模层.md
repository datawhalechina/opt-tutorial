# 第 8 章 建模层：PuLP 与 Pyomo

前面七章都是直接调求解器的原生接口。如果你只用一个求解器，这样最直接；但只要遇到下面任一情况，就该考虑建模层：

- 同一份模型要在 Gurobi / COPT / HiGHS 之间对比性能
- 团队里有人用 Gurobi、有人用 COPT，模型想共用
- 想先用免费求解器开发，上线再换商用求解器

**建模层 = 模型写一次，求解器随便换。**

## 8.1 PuLP：最轻量的选择

PuLP 语法极简，适合 LP / MILP，内置 CBC，也能调 HiGHS、COPT 等后端。

```python
import pulp

model = pulp.LpProblem("FacilityLocation", pulp.LpMinimize)

y = [pulp.LpVariable(f"y{i+1}", cat="Binary") for i in range(n_fac)]
x = {(i, j): pulp.LpVariable(f"x{i+1}{j+1}", lowBound=0)
     for i in range(n_fac) for j in range(n_cus)}

model += (pulp.lpSum(fixed[i] * y[i] for i in range(n_fac))
          + pulp.lpSum(cost[i][j] * x[i, j] for i in range(n_fac) for j in range(n_cus)))

for j in range(n_cus):
    model += pulp.lpSum(x[i, j] for i in range(n_fac)) == demand[j], f"demand{j+1}"
for i in range(n_fac):
    model += pulp.lpSum(x[i, j] for j in range(n_cus)) <= big_m * y[i], f"open_link{i+1}"

model.solve(pulp.HiGHS(msg=False))     # ← 只改这一行就能换后端
print(pulp.value(model.objective), pulp.LpStatus[model.status])
```

三个语法点：

- `model += 表达式`：不带逗号是**目标函数**，带 `, "名字"` 是**约束**
- 求和用 `pulp.lpSum()`，不是内置 `sum()`
- `cat="Binary"` 是 0-1，`cat="Integer"` 是整数，不写就是连续

### 换后端只改一行

实测可用的后端（PuLP 3.3）：

| 后端 | 写法 | 说明 |
| :--- | :--- | :--- |
| CBC | `pulp.PULP_CBC_CMD(msg=False)` | 内置，装 PuLP 就有，最省事 |
| HiGHS | `pulp.HiGHS(msg=False)` | 开源，比 CBC 快不少 |
| COPT | `pulp.COPT(msg=False)` | 需 `pip install coptpy` |
| Gurobi | `pulp.GUROBI(msg=False)` | 需 license |
| SCIP | `pulp.SCIP_PY(msg=False)` | 需 `pip install pyscipopt` |

```python
for backend in [pulp.PULP_CBC_CMD(msg=False), pulp.HiGHS(msg=False), pulp.COPT(msg=False)]:
    model.solve(backend)               # 同一个 model 对象反复用
    print(backend, pulp.value(model.objective))
```

三个后端算出来都是 273 —— 这也是"换后端不影响结果"的直接证据。

## 8.2 Pyomo：更适合工程化

Pyomo 的表达能力比 PuLP 强（支持索引集合、分段线性、微分代数方程等），而且**模型和求解器彻底解耦**：模型只描述数学，`SolverFactory` 负责换成任何后端，甚至能调 GAMS/AMPL 求解器。

```python
import pyomo.environ as pyo

model = pyo.ConcreteModel("FacilityLocation")
model.FAC = pyo.RangeSet(0, n_fac - 1)
model.CUS = pyo.RangeSet(0, n_cus - 1)
model.ARC = pyo.Set(initialize=[(i, j) for i in range(n_fac) for j in range(n_cus)])

model.y = pyo.Var(model.FAC, domain=pyo.Binary)
model.x = pyo.Var(model.ARC, domain=pyo.NonNegativeReals)

model.cost = pyo.Objective(
    expr=sum(fixed[i] * model.y[i] for i in model.FAC)
    + sum(cost[i][j] * model.x[i, j] for i, j in model.ARC),
    sense=pyo.minimize,
)

# 用 rule= 描述"对每个下标要满足什么"，这是 Pyomo 最好用的地方
model.demand = pyo.Constraint(
    model.CUS, rule=lambda m, j: sum(m.x[i, j] for i in m.FAC) == demand[j]
)
model.open_link = pyo.Constraint(
    model.FAC, rule=lambda m, i: sum(m.x[i, j] for j in m.CUS) <= big_m * m.y[i]
)

result = pyo.SolverFactory("appsi_highs").solve(model)
print(pyo.value(model.cost), result.solver.termination_condition)
```

### 换后端只改一个字符串

| 后端名 | 需要什么 |
| :--- | :--- |
| `appsi_highs` / `highs` | `pip install highspy`，**零配置，推荐** |
| `gurobi_direct` | `gurobipy` + license |
| `cplex_direct` | `cplex` 模块 + CPLEX 运行时 |
| `copt_direct` | `coptpy` + COPT 授权 |
| `cbc` / `glpk` / `scip` | 需要对应的**命令行可执行文件**（shell 接口），只 pip 装 Python 包不够 |

```python
result = pyo.SolverFactory("appsi_highs").solve(model)
print(pyo.value(model.cost))
```

⚠️ 一个容易误解的点：Pyomo 的 `scip` 后端调用的是 SCIP 的 **ASL 可执行文件**，装了 `pyscipopt` 并不等于这个后端可用。想用 SCIP 的 Python 接口，还是走第 7 章那样直接 `from pyscipopt import Model`。

## 8.3 该用哪个？

| 场景 | 建议 |
| :--- | :--- |
| 只用一个求解器、追求极致性能 | 直接用原生 API（第 1~7 章） |
| 多做求解器对比、模型复用 | PuLP（简单）或 Pyomo（表达力强） |
| 需要指示约束、懒约束、回调 | 原生 API；PuLP 支持懒约束，Pyomo 支持大部分高级特性 |
| 需要调 GAMS / AMPL / 商业求解器全家桶 | Pyomo |

**性能和灵活性的真实差别**：原生 API 可以直接访问每个求解器的特性（Gurobi 的 callback、COPT 的 `addQConstr`、SCIP 的插件），建模层则只能暴露各家的交集。所以"生产环境用原生、实验阶段用建模层"是常见组合。
