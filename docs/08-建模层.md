# 第 8 章 建模层：PuLP 与 Pyomo

前面七章都是直接调求解器的原生接口。如果你只用一个求解器，这样最直接；但只要遇到下面任一情况，就该考虑建模层：

- 同一份模型要在 Gurobi / COPT / HiGHS 之间对比性能
- 团队里有人用 Gurobi、有人用 COPT，模型想共用
- 想先用免费求解器开发，上线再换商用求解器

**建模层 = 模型写一次，求解器随便换。**

## 8.1 PuLP：最轻量的选择

PuLP 语法极简，适合 LP / MILP，内置 CBC，也能调 HiGHS、COPT 等后端。

```python
import pulp

n_fac, n_cus = 3, 4
fixed = [35, 45, 55]
demand = [10, 15, 12, 8]
cost = [[4, 6, 9, 7], [8, 3, 5, 6], [6, 7, 4, 5]]
big_m = sum(demand)                      # 45，big-M 用总需求就够紧

model = pulp.LpProblem("FacilityLocation", pulp.LpMinimize)

y = [pulp.LpVariable(f"y{i+1}", cat="Binary") for i in range(n_fac)]
x = {(i, j): pulp.LpVariable(f"x{i+1}{j+1}", lowBound=0)
     for i in range(n_fac) for j in range(n_cus)}

model += (pulp.lpSum(fixed[i] * y[i] for i in range(n_fac))
          + pulp.lpSum(cost[i][j] * x[i, j] for i in range(n_fac) for j in range(n_cus)))

for j in range(n_cus):
    model += pulp.lpSum(x[i, j] for i in range(n_fac)) == demand[j], f"demand{j+1}"
for i in range(n_fac):
    model += pulp.lpSum(x[i, j] for j in range(n_cus)) <= big_m * y[i], f"open_link{i+1}"

model.solve(pulp.HiGHS(msg=False))     # ← 只改这一行就能换后端
print(pulp.value(model.objective), pulp.LpStatus[model.status])
```

四个语法点：

- **判定依据是比较符，不是逗号**：`model += expr <= 100` 是约束，`model += expr` 是目标函数；`, "名字"` 只是给这个对象起名。
- ⚠️ **`model += 裸表达式, "名字"` 是"有名字的目标函数"**，不是约束。写第二次会**静默覆盖**上一个目标（只发一条 `UserWarning: Overwriting previously set objective.`），一个模型只能有一个 `model += 裸表达式`。
- 求和建议用 `pulp.lpSum()`：与内置 `sum()` 结果等价，但对线性表达式做了优化，更快，且空和返回 `0.0`（内置 `sum([])` 返回 `int 0`，参与运算容易出隐性 bug）。
- `cat="Binary"` 是 0-1，`cat="Integer"` 是整数，不写就是连续。

### 换后端只改一行

常见后端及依赖（PuLP 3.3）：

| 后端 | 写法 | 需要什么 |
| :--- | :--- | :--- |
| CBC | `pulp.PULP_CBC_CMD(msg=False)` | 装 PuLP 就自带，最省事 |
| HiGHS | `pulp.HiGHS(msg=False)` | `pip install highspy` |
| COPT | `pulp.COPT(msg=False)` | `pip install coptpy` + 有效授权 |
| SCIP | `pulp.SCIP_PY(msg=False)` | `pip install pyscipopt` |
| Gurobi | `pulp.GUROBI(msg=False)` | `pip install gurobipy` + license |

```python
for backend in [pulp.PULP_CBC_CMD(msg=False), pulp.HiGHS(msg=False), pulp.COPT(msg=False)]:
    model.solve(backend)
    assert pulp.LpStatus[model.status] == "Optimal", pulp.LpStatus[model.status]
    print(type(backend).__name__, pulp.value(model.objective))
```

本机实测这三个后端都给出 273。⚠️ 必须每次判状态：PuLP 重复求解**不会清空变量值**，`pulp.value()` 是拿上一次的残留值重新算表达式，不可行时也会打印一个看着很像答案的假数值。

> 版本提示：PuLP 3.3 已把 `LpVariable(name, ...)` 直接构造标记为 deprecated，4.0 会改成 `prob.add_variable(...)`。本仓库代码按 3.x 写法，`requirements.txt` 里限定 `pulp<4`。

## 8.2 Pyomo：更适合工程化

Pyomo 的表达能力比 PuLP 强（支持索引集合、分段线性、微分代数方程等），而且**模型和求解器彻底解耦**：模型只描述数学，`SolverFactory` 负责换成任何后端，甚至能调 GAMS/AMPL 求解器。

数据沿用上一节的设施选址（`n_fac=3`、`n_cus=4`、`fixed`、`demand`、`cost`、`big_m`）：

```python
import pyomo.environ as pyo

model = pyo.ConcreteModel("FacilityLocation")
model.FAC = pyo.RangeSet(0, n_fac - 1)
model.CUS = pyo.RangeSet(0, n_cus - 1)
model.ARC = pyo.Set(initialize=[(i, j) for i in range(n_fac) for j in range(n_cus)])

model.y = pyo.Var(model.FAC, domain=pyo.Binary)
model.x = pyo.Var(model.ARC, domain=pyo.NonNegativeReals)

# 求和用 pyo.quicksum，和 PuLP 的 lpSum 对应，大模型下比内置 sum 快一个量级
model.objective = pyo.Objective(
    expr=pyo.quicksum(fixed[i] * model.y[i] for i in model.FAC)
    + pyo.quicksum(cost[i][j] * model.x[i, j] for i, j in model.ARC),
    sense=pyo.minimize,
)

# 用 rule= 描述"对每个下标要满足什么"，这是 Pyomo 最好用的地方
model.demand = pyo.Constraint(
    model.CUS, rule=lambda m, j: pyo.quicksum(m.x[i, j] for i in m.FAC) == demand[j]
)
model.open_link = pyo.Constraint(
    model.FAC, rule=lambda m, i: pyo.quicksum(m.x[i, j] for j in m.CUS) <= big_m * m.y[i]
)

solver = pyo.SolverFactory("appsi_highs")
result = solver.solve(model)
print(pyo.value(model.objective), result.solver.termination_condition)
```

### 换后端只改一个字符串

| 后端名 | 需要什么 | 本机实测 |
| :--- | :--- | :--- |
| `appsi_highs` / `highs` | `pip install highspy`（无需 license、无需命令行程序，推荐） | ✅ 可用 |
| `gurobi_direct` | `gurobipy` + license | 需 license |
| `cplex_direct` | `cplex` 模块 + CPLEX 运行时 | 需运行时 |
| `cbc` / `glpk` / `scip` | 需要对应的**命令行可执行文件**（shell 接口），只 pip 装 Python 包不够 | ❌ 不可用 |

```python
solver = pyo.SolverFactory("appsi_highs")
if not solver.available(exception_flag=False):
    raise RuntimeError("后端不可用：先 pip install highspy")
result = solver.solve(model)
print(pyo.value(model.objective), result.solver.termination_condition)
```

三个容易误解的点：

1. **Pyomo 没有 `copt_direct`**（6.10.1 里不存在这个名字）；想用 COPT 走 `pulp.COPT` 或原生 `coptpy`。
2. **名字写错不会报错**：`SolverFactory("随便写")` 返回一个 `UnknownSolver`，`available()` 才是 `False`。所以一定要先探测。
3. **`scip` 后端 ≠ pyscipopt**：它调的是 SCIP 的 **ASL 可执行文件**，装了 `pyscipopt` 不代表可用。想用 SCIP 的 Python 接口，直接 `from pyscipopt import Model`（第 7 章）。

另外，`pip install pyomo` **不带任何求解器**，必须自己再装后端。

## 8.3 该用哪个？

| 场景 | 建议 |
| :--- | :--- |
| 只用一个求解器、追求极致性能 | 直接用原生 API（第 1~7 章） |
| 多做求解器对比、模型复用 | PuLP（简单）或 Pyomo（表达力强） |
| 需要指示约束、懒约束、回调 | 原生 API。**PuLP 没有任何懒约束/回调接口**（只在个别后端透传裸 callback），Pyomo 也要靠特定后端 |
| 需要调 GAMS / AMPL / 商业求解器全家桶 | Pyomo |

**性能和灵活性的真实差别**：原生 API 可以直接访问每个求解器的特性（Gurobi 的 callback、COPT 的 `addQConstr`、SCIP 的插件），建模层则只能暴露各家的交集。所以"生产环境用原生、实验阶段用建模层"是常见组合。
