# 第 7 章 车辆路径问题（CVRP）

前面几章都是"教科书例题"。这一章看一个真问题：带容量约束的车辆路径问题（Capacitated Vehicle Routing Problem）。

## 7.1 问题

1 个配送中心（节点 0）+ 5 个客户，车辆载重上限 15：

| 节点 | 坐标 | 需求 |
| :---: | :--- | ---: |
| 0（中心） | (35, 35) | 0 |
| 1 | (41, 49) | 7 |
| 2 | (35, 17) | 4 |
| 3 | (55, 45) | 3 |
| 4 | (55, 20) | 5 |
| 5 | (15, 30) | 2 |

总需求 21，单车载重 15，所以至少要两辆车。目标是**总行驶距离最短**。

## 7.2 模型

**变量**

- $x_{ij} \in \{0,1\}$：车是否从 $i$ 直接开到 $j$
- $u_i$：车辆离开客户 $i$ 时车上的累计载货量

**目标**

$$
\min \sum_{i}\sum_{j \ne i} d_{ij} x_{ij}
$$

**约束**

$$
\begin{aligned}
& \sum_{j \ne i} x_{ij} = 1 && \forall i \in \text{客户} \quad\text{每个客户被离开一次}\\
& \sum_{i \ne j} x_{ij} = 1 && \forall j \in \text{客户} \quad\text{每个客户被进入一次}\\
& u_j \ge u_i + q_j - Q(1 - x_{ij}) && \forall i \ne j,\ i,j \in \text{客户}\\
& q_i \le u_i \le Q && \forall i \in \text{客户}\\
& \sum_j x_{0j} = \sum_i x_{i0} && \text{出发车数 = 回到中心的车数}
\end{aligned}
$$

第三条就是 **MTZ 子回路消除约束**：如果 $i \to j$ 被选中（$x_{ij}=1$），承载量必须单调增加 $q_j$；否则退化成 $u_j \ge u_i + q_j - Q$，因为 $Q$ 是载重上限，这条永远成立。这样任何脱离中心的死循环都会被排掉。

> MTZ 的缺点：它是"弱"约束，LP 松弛松，规模大了节点数会爆炸。客户上千时要换成基于集合划分的列生成（branch-and-price）。这一章用 MTZ 是因为小规模够用，而且**五个求解器都能直接写**（不依赖指示约束）。

## 7.3 求解结果

```
路线 0 -> 1 -> 3 -> 0，载重 10/15
路线 0 -> 5 -> 2 -> 4 -> 0，载重 11/15
最优目标值 = 141.84
```

COPT、HiGHS、SCIP 三个求解器都是 **141.84**。

顺带一个值得注意的现象：HiGHS 给出的是 `0 -> 3 -> 1 -> 0`，路线方向反了，但距离完全相同。这是**多重最优解**——倒着走同一条路，距离一样。拿解做业务决策时要知道"最优解可能不唯一"。

## 7.4 Gurobi 写法（其余求解器见代码目录）

```python
x = model.addVars(arcs, vtype=GRB.BINARY, name="x")
u = model.addVars(customers, lb=0, name="u")

model.setObjective(gp.quicksum(dist[i, j] * x[i, j] for i, j in arcs), GRB.MINIMIZE)

for i in customers:                       # 出度
    model.addConstr(gp.quicksum(x[i, j] for j in nodes if j != i) == 1, name=f"out_{i}")
for j in customers:                       # 入度
    model.addConstr(gp.quicksum(x[i, j] for i in nodes if i != j) == 1, name=f"in_{j}")

for i in customers:
    model.addConstr(u[i] >= demand[i], name=f"load_lb_{i}")
    model.addConstr(u[i] <= capacity, name=f"load_ub_{i}")
for i in customers:                       # MTZ
    for j in customers:
        if i != j:
            model.addConstr(u[j] >= u[i] + demand[j] - capacity * (1 - x[i, j]),
                            name=f"mtz_{i}_{j}")
```

变量直接用 `arcs` 这个二元组列表批量建（`addVars(arcs, …)`），取用时写 `x[i, j]`，比手动拼下标干净。

## 7.5 各求解器批量建变量的写法

| 求解器 | 用二元组列表批量建变量 |
| :--- | :--- |
| Gurobi | `model.addVars(arcs, vtype=GRB.BINARY, name="x")` |
| COPT | `model.addVars(arcs, vtype=COPT.BINARY, nameprefix="x")` |
| CPLEX | `model.binary_var_dict(arcs, name="x")`（字典，不是矩阵） |
| HiGHS | 字典推导 `{(i,j): model.addVariable(...) for i,j in arcs}` |
| SCIP | 字典推导 `{(i,j): model.addVar(vtype="B") for i,j in arcs}` |
