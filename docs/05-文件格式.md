# 第 5 章 求解器常用文件格式

模型写好后，为什么还要关心文件格式？三个场景离不开它：

1. **交接**：同事用 Gurobi、你用 COPT，导一个 MPS 给对方即可，不用重写代码
2. **排查**：模型跑出奇怪结果，把 LP 文件导出来肉眼看一遍最快
3. **复用**：把解存成文件，下次求解时当起始解（热启动）

## 5.1 格式一览

| 后缀 | 用途 | 能否读回 | 说明 |
| :--- | :--- | :---: | :--- |
| `.lp` | 模型 | ✅ | 纯文本、人可读。⚠️ 读回时不保证列顺序，也通常不保持系数的精确值 |
| `.mps` | 模型 | ✅ | 工业标准，有 fixed / free 两种写法（求解器写出的通常是 free）。**跨求解器交换优先用它** |
| `.rew` | 模型 | ✅ | MPS 的一种变体，保留系数精确值 |
| `.sol` | 解 | ✅ | 保存**所有**变量的解值，可读回来当起始解（Python 里用 `model.read()`） |
| `.mst` | 解（MIP start） | ✅ | 给 MIP 提供起始解的格式。⚠️ 官方说明写 `.mst` 时**不保存连续变量的值**，完整解请用 `.sol` |
| `.json` | 解 + 求解统计 | ❌ 只写 | 除了变量值还带 Status/ObjVal/NodeCount 等，喂程序或看板用，**不是模型文件** |
| `.bas` | 单纯形基 | ✅ | 只对**连续模型**有意义；MIP 没有基，写出来是空的 |
| `.prm` / `.par` | 参数设置 | ✅ | Gurobi 用 `.prm`，COPT 用 `.par`（写错后缀不报错，但**不生成文件**） |
| `.ilp` | IIS 模型 | ✅ | 语法与 `.lp` 完全相同，**专门用于写 IIS**（不可约冲突集） |
| `.iis` | IIS 模型 | ✅ | COPT 的 IIS 后缀，别照抄 Gurobi 的 `.ilp` |

两个最容易记错的地方：

- **`.sol` 是可以读回来的**，只是要用 `model.read()`，不能用 `gp.read()`——后者只建模型，不读解。Gurobi 官方文件格式页把 SOL / JSON / MST / BAS 都归在"Solution File Formats"，明确写了"all solution file formats can be used to import solution information"。
- **`.ilp` 就是 IIS 专用格式**（官方原文：*This format is identical to the LP format but it is used for Irreducible Inconsistent Subsystem (IIS) models*）。语法同 LP，用途专一。

## 5.2 MPS 文件长什么样

```
NAME          TESTPROB
OBJSENSE
    MAX
ROWS
 N  COST
 L  LIM1
 G  LIM2
COLUMNS
    XONE      COST       1
    XONE      LIM1       2
    YTWO      COST       4
    YTWO      LIM2       3
RHS
    RHS1      LIM1       5
    RHS1      LIM2      10
BOUNDS
 UP BND1      XONE       1
 LO BND1      YTWO       0
ENDATA
```

| 段 | 作用 |
| :--- | :--- |
| `NAME` | 模型名，可选 |
| `OBJSENSE` | 最大化还是最小化，**不写默认最小化** |
| `ROWS` | 行：`N` 目标函数、`L` ≤、`G` ≥、`E` = |
| `COLUMNS` | 变量的非零系数，同一变量的行必须连续 |
| `RHS` | 约束右端项 |
| `RANGES` | 区间约束的宽度，可选 |
| `BOUNDS` | 变量上下界，默认 $[0,+\infty)$ |
| `ENDATA` | 结束 |

`BOUNDS` 常用类型：`UP` 上界、`LO` 下界、`FX` 固定值、`FR` 自由变量、`MI` 下界 $-\infty$、`PL` 上界 $+\infty$、`BV` 0-1、`LI/UI` 整数上下界、`SC/SI` 半连续/半整数。

## 5.3 LP 文件长什么样

```
\ 反斜杠后面是注释
Maximize
  obj: 40 A + 50 B

Subject To
  Production_Time: 2 A + 4 B <= 100
  Raw_Material: 3 A + B <= 50

Bounds
  A >= 0
  B >= 0

End
```

规则很简单：关键词分行、表达式用 `+ - *` 拼、变量名之间必须有空格（`A+B` 会被当成一个变量名）。

> 上面就是第 1 章那道生产题的 LP 形式。**别在这里加 `Generals A B`**——那是声明整数变量，会把连续 LP 变成整数规划，读回来求的就不是同一个问题了。

二次约束用方括号包起来：

```
qc0: x + y + [ x ^ 2 - 2 x * y + 3 y ^ 2 ] <= 5
```

## 5.4 各求解器读写 API

| 操作 | Gurobi | COPT | CPLEX (docplex) | HiGHS | SCIP |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 读模型 | `gp.read("m.mps")` | `model.read("m.mps")` | `ModelReader().read("m.lp")` ⚠️需运行时 | `model.readModel("m.mps")` | `model.readProblem("m.mps")` |
| 写模型 | `model.write("m.lp")` | `model.write("m.lp")` | `model.export_as_lp("m.lp")` | `model.writeModel("m.lp")` | `model.writeProblem("m.lp")` |
| 写解 | `model.write("s.sol")` | `model.write("s.sol")` | `solution.export_as_sol("s.sol")` | `model.writeSolution("s.sol", 0)` | `model.writeSol("s", "s.sol")` |
| 读起始解 | `model.read("s.sol")` | `model.read("s.sol")` | `model.read_mip_starts("s.mst")` | `model.readSolution("s.sol", 0)` | `model.readSol("s.sol")` |
| IIS | `computeIIS()` + `write("c.ilp")` | `computeIIS()` + `writeIIS("c.iis")` | 冲突精化（需运行时） | `getIis()` + `writeIisModel()` | `generateIIS()` |

⚠️ 四个必须注意的点：

1. **COPT 没有全局的 `cp.read()`**，必须先建环境和模型，再 `model.read()`；写 `cp.read("x.mps")` 会报 `AttributeError`。
2. **HiGHS 的 `readSolution` 要两个参数**：`readSolution("s.sol", 0)`，第二个参数是解文件格式（0 = raw），少传直接 `TypeError`。同样，`writeSolution` 也是两个参数。
3. **SCIP 的 `readSol` 必须在 `optimize()` 之前调用**，求解完再读会抛"method cannot be called at this time"。
4. **`gp.read()` 能读的模型后缀**是 `.mps/.rew/.lp/.rlp/.dua/.dlp/.ilp/.opb`；`model.read()` 读的是解/基/参数文件（`.sol/.mst/.bas/.prm` 等）。注意 Python 接口里 `read.__doc__` 的列表比官方文档旧，以[官方文件格式页](https://docs.gurobi.com/projects/optimizer/en/current/reference/misc/fileformats.html)为准。

### docplex 的特殊之处

- 导出模型：`export_as_lp()` **不需要** CPLEX 运行时；`export_as_mps()` **需要**运行时（MPS 导出走引擎）。
- 导出解：用解对象自己的方法 `solution.export_as_sol("s.sol")`，而不是 `model.export_basis()`（那写的是基，不是解，而且要求模型已求解）。
- 导出参数：`model.export_parameters_as_prm("p.prm")`。`model.export_prm()` **不存在**。

## 5.5 导不出结果？先查 IIS

模型不可行（infeasible）时，求解器只会告诉你"无解"。想知道是哪几条约束打架，要让它算 **IIS**（Irreducible Inconsistent Subsystem，不可约冲突集）——去掉其中任意一条，剩下的就可行了。

```python
# Gurobi：写成 .ilp
model.optimize()
if model.Status == GRB.INFEASIBLE:
    model.computeIIS()
    model.write("conflict.ilp")

# COPT：写成 .iis（不是 .ilp）
bad.solve()
if bad.status == COPT.INFEASIBLE:
    bad.computeIIS()
    bad.writeIIS("conflict.iis")

# HiGHS：1.16 起有 getIis / writeIisModel
status, iis = model.getIis()
model.writeIisModel("conflict.lp")

# SCIP：先生成，再从子 SCIP 里取冲突约束
iis = model.generateIIS()
print([c.name for c in iis.getSubscip().getConss()])
```

COPT 写 `.ilp` 不会报错，但**不会生成文件**——后缀必须是 `.iis`，这是最容易被 Gurobi 习惯带偏的坑。

只拿到 IIS 还不够：多个独立冲突要逐个修，“最少改多少就可行”怎么算，见[第 10 章](./10-不可行模型排查.md)。
