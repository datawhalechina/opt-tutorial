# 第 5 章 求解器常用文件格式

模型写好后，为什么还要关心文件格式？三个场景离不开它：

1. **交接**：同事用 Gurobi、你用 COPT，导一个 MPS 给对方即可，不用重写代码
2. **排查**：模型跑出奇怪结果，把 LP 文件导出来肉眼看一遍最快
3. **复用**：把解存成文件，下次求解时当热启动（warm start）

## 5.1 格式一览

| 后缀 | 用途 | 能否读回 | 说明 |
| :--- | :--- | :---: | :--- |
| `.lp` | 模型 | ✅ | 纯文本，人可读，最常用 |
| `.mps` | 模型 | ✅ | 工业标准，字段定长，兼容性最好 |
| `.mst` | MIP 起始解 | ✅ | 热启动，把上次的解当初始解 |
| `.bas` | 单纯形基底 | ✅ | 连续模型的热启动 |
| `.sol` | 解 | ❌ 只写 | 老式格式，常见求解器都能写，但**读不回来** |
| `.prm` | 参数设置 | ✅ | 一堆 `ParamName value` |
| `.ilp` | 整数模型（LP 语法） | ✅ | 也是 Gurobi 存 IIS 冲突集用的格式 |
| `.json` | 模型 + 解的完整信息 | ✅ | Gurobi 独有，信息最全 |

两个必须记住的结论：

- **`.sol` 不要试图用 `read()` 读回来**。Gurobi 的 `read()` 只认 `.lp/.mps/.rew/.rlp`，`Model.read()` 只认 `.mst/.bas/.prm`。要交换解请用 `.mst`。
- **`.ilp` 不是"IIS 专用格式"**。它本质就是 LP 语法，只是变量声明成整数；Gurobi 把不可约冲突集（IIS）写成 `.ilp`，是因为 IIS 正好可以用"一组 LP 约束"表示，去掉其余约束而已。

## 5.2 MPS 文件长什么样

```
NAME          TESTPROB
OBJSENSE
    MAX
ROWS
 N  COST
 L  LIM1
 G  LIM2
COLUMNS
    XONE      COST       1
    XONE      LIM1       2
    YTWO      COST       4
    YTWO      LIM2       3
RHS
    RHS1      LIM1       5
    RHS1      LIM2      10
BOUNDS
 UP BND1      XONE       1
 LO BND1      YTWO       0
ENDATA
```

| 段 | 作用 |
| :--- | :--- |
| `NAME` | 模型名，可选 |
| `OBJSENSE` | 最大化还是最小化，**不写默认最小化** |
| `ROWS` | 行：`N` 目标函数、`L` ≤、`G` ≥、`E` = |
| `COLUMNS` | 变量的非零系数，同一变量的行必须连续 |
| `RHS` | 约束右端项 |
| `RANGES` | 区间约束的宽度，可选 |
| `BOUNDS` | 变量上下界，默认 $[0,+\infty)$ |
| `ENDATA` | 结束 |

`BOUNDS` 常用类型：`UP` 上界、`LO` 下界、`FX` 固定值、`FR` 自由变量、`MI` 下界 $-\infty$、`PL` 上界 $+\infty$、`BV` 0-1、`LI/UI` 整数上下界、`SC/SI` 半连续/半整数。

## 5.3 LP 文件长什么样

```
\ 反斜杠后面是注释
Maximize
  obj: 40 A + 50 B

Subject To
  Production_Time: 2 A + 4 B <= 100
  Raw_Material: 3 A + B <= 50

Bounds
  0 <= A <= 100
  B >= 0

Generals
  A B

End
```

规则很简单：关键词分行、表达式用 `+ - *` 拼、变量名之间必须有空格（`A+B` 会被当成一个变量名）。二次约束用方括号包起来：

```
qc0: x + y + [ x ^ 2 - 2 x * y + 3 y ^ 2 ] <= 5
```

## 5.4 各求解器读写 API

| 操作 | Gurobi | COPT | CPLEX (docplex) | HiGHS | SCIP |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 读模型 | `gp.read("m.mps")` | `model.read("m.mps")` | `ModelReader().read("m.lp")` | `model.readModel("m.mps")` | `model.readProblem("m.mps")` |
| 写模型 | `model.write("m.lp")` | `model.write("m.lp")` | `model.export_as_lp("m.lp")` | `model.writeModel("m.lp")` | `model.writeProblem("m.lp")` |
| 写解 | `model.write("s.mst")` | `model.write("s.sol")` | `model.export_basis(…)` | `model.writeSolution("s.sol", 0)` | `model.writeSol(sol, "s.sol")` |
| 读热启动 | `model.read("s.mst")` | — | `model.read_mip_starts("s.mst")` | `model.readSolution("s.sol")` | `model.readSol("s.sol")` |

⚠️ **COPT 没有全局的 `cp.read()`**，必须先建环境和模型再 `model.read()`；也不要写 `cp.read("x.mps")`（会报 `AttributeError`）。

## 5.5 导不出结果？先查 IIS

模型不可行（infeasible）时，求解器只会告诉你"无解"。想知道是哪几条约束打架，要让它算 **IIS**（Irreducible Inconsistent Subsystem，不可约冲突集）——去掉其中任意一条，剩下的就可行了。

```python
# Gurobi
model.optimize()
if model.Status == GRB.INFEASIBLE:
    model.computeIIS()
    model.write("conflict.ilp")       # 导出的文件里就是冲突的那几条约束
```

COPT 也是 `model.computeIIS()` + `model.write("conflict.ilp")`。CPLEX 走冲突精化（conflict refiner）路线，HiGHS 和 SCIP 没有一键 IIS，一般靠逐步注释约束定位。
