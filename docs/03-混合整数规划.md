# 第 3 章 混合整数规划问题

混合整数规划（Mixed-Integer Programming, MIP）是最贴近实际的一类问题：**一部分决策是"开/不开"这种 0-1 决策，一部分是"发多少货"这种连续量**。

$$
\begin{aligned}
\min \quad & \mathbf{c}^\top \mathbf{x} \\
\text{s.t.} \quad & \mathbf{A}\mathbf{x} \le \mathbf{b} \\
& x_i \in \mathbb{Z}\ (i \in \mathcal{I}),\quad x_j \in \mathbb{R}\ (j \in \mathcal{C})
\end{aligned}
$$

## 3.1 例题：设施选址

3 个候选仓库、4 个客户。

- 开仓固定成本：仓库 1 = 35、仓库 2 = 45、仓库 3 = 55
- 客户需求：10、15、12、8
- 单位运输成本：

| 仓库 \ 客户 | 1 | 2 | 3 | 4 |
| :--- | ---: | ---: | ---: | ---: |
| 1 | 4 | 6 | 9 | 7 |
| 2 | 8 | 3 | 5 | 6 |
| 3 | 6 | 7 | 4 | 5 |

**变量**

- $y_i \in \{0,1\}$：是否在仓库 $i$ 开仓
- $x_{ij} \ge 0$：从仓库 $i$ 发给客户 $j$ 的量

**目标与约束**

$$
\begin{aligned}
\min \quad & \sum_i f_i y_i + \sum_i \sum_j c_{ij} x_{ij} \\
\text{s.t.} \quad & \sum_i x_{ij} = d_j && \forall j \quad\text{需求必须满足}\\
& \sum_j x_{ij} \le M y_i && \forall i \quad\text{开了仓才能发货}\\
& y_i \in \{0,1\},\ x_{ij} \ge 0
\end{aligned}
$$

第二条就是 **big-M 约束**：$M$ 取客户总需求量（$\sum_j d_j = 45$）就够，$y_i=0$ 时右边为 0，发货量被迫为 0。

最优解：开 1、2 号仓，总成本 **273**。

## 3.2 Gurobi 写法

```python
import gurobipy as gp
from gurobipy import GRB

model = gp.Model("FacilityLocation")
y = model.addVars(3, vtype=GRB.BINARY, name="y")
x = model.addVars(3, 4, lb=0, name="x")          # 二维变量，取用时写 x[i, j]

model.setObjective(
    gp.quicksum(fixed[i] * y[i] for i in range(3))
    + gp.quicksum(cost[i][j] * x[i, j] for i in range(3) for j in range(4)),
    GRB.MINIMIZE,
)

# 批量约束：addConstrs 收一个生成器
model.addConstrs(
    (gp.quicksum(x[i, j] for i in range(3)) == demand[j] for j in range(4)),
    name="demand",
)
model.addConstrs(
    (gp.quicksum(x[i, j] for j in range(4)) <= sum(demand) * y[i] for i in range(3)),
    name="open_link",
)

model.optimize()
print(model.ObjVal)      # 273
```

> 也可以按客户逐个写：`x[i, j] <= d[j] * y[i]`，同样正确，只是约束从 3 条变成 12 条，且 big-M 用各自的 $d_j$。用"整行发货量 ≤ 客户总需求 × 是否开仓"更紧凑，本仓库用的是后一种。

## 3.3 COPT 写法

和 Gurobi 几乎一样，只有三处差别：

```python
env = cp.Envr()
model = env.createModel("FacilityLocation")

y = model.addVars(3, vtype=COPT.BINARY, nameprefix="y")
x = model.addVars(3, 4, lb=0, vtype=COPT.CONTINUOUS, nameprefix="x")

model.setObjective(..., sense=COPT.MINIMIZE)

model.addConstrs((... for j in range(4)), nameprefix="demand")     # 批量用 nameprefix
model.solve()                                                       # 求解用 solve()
```

## 3.4 三种写法要点

| 操作 | Gurobi | COPT | CPLEX (docplex) | HiGHS | SCIP |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 二维变量 | `addVars(m, n)` 取 `x[i, j]` | `addVars(m, n, nameprefix="x")` | `continuous_var_matrix(m, n)` | 字典推导 `{(i,j): addVariable()}` | 字典推导 |
| 批量约束 | `addConstrs(gen, name=)` | `addConstrs(gen, nameprefix=)` | `add_constraints(gen, names=[…])` | 循环 `addConstr` | 循环 `addCons` |
| 求和 | `quicksum` | `quicksum` | `model.sum` | 内置 `sum` | `quicksum` |

CPLEX 的批量约束支持 `names=` 一次给一批名字，比较方便：

```python
model.add_constraints(
    (model.sum(x[i, j] for i in range(3)) == demand[j] for j in range(4)),
    names=[f"demand{j+1}" for j in range(4)],
)
```

## 3.5 big-M 怎么取值

big-M 是"足够大"的常数，**不能随便填 1e9**：

- 太大 → LP 松弛很弱，分支定界树爆炸；数值上还可能出现 $10^9 \times 10^{-8}$ 这类精度问题
- 太小 → 把可行解切掉了，结果是错的

正确做法是取**问题自身的物理上界**。上面"整行发货量 ≤ 客户总需求"，总需求就是天然的上界，既紧又不会切错。下一章的"最小起运量"同理，用产能做上界。
