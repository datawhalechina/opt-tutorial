# 第 0 章 环境准备

这一章只做一件事：把求解器装好、能跑通。装完执行一条命令就知道环境对不对。

## 0.1 五个求解器，先认识一下

| 求解器 | 类型 | Python 包 | 授权 | 官方文档 |
| :--- | :--- | :--- | :--- | :--- |
| **Gurobi** | 商用 | `gurobipy` | 需申请 license（学生/学术免费一年） | [文档](https://docs.gurobi.com/projects/optimizer/en/current/index.html) · [示例](https://docs.gurobi.com/projects/examples/en/current/) |
| **COPT** | 商用（国产） | `coptpy` | 自带受限试用 license，商用需购买 | [文档](https://www.shanshu.ai/copt-document/) · [Python 指南](https://guide.coap.online/copt/zh-doc/) |
| **CPLEX** | 商用 | `docplex` | 需 CPLEX 运行时；小模型可用社区版 | [文档](https://www.ibm.com/docs/en/icos) · [docplex](https://ibmdecisionoptimization.github.io/docplex-doc/) |
| **HiGHS** | 开源（MIT） | `highspy` | 无需授权 | [文档](https://ergo-code.github.io/HiGHS/) · [Python 接口](https://ergo-code.github.io/HiGHS/dev/interfaces/python/) |
| **SCIP** | 开源（Apache 2.0，8.0.3 起可商用） | `pyscipopt` | 无需授权 | [文档](https://scipopt.org/doc/html/) · [PySCIPOpt](https://pyscipopt.readthedocs.io/) |

> 一句话选型：**学习/写论文**用 HiGHS 或 SCIP 起步，零成本；**工业落地**用 Gurobi / COPT / CPLEX，规模大、求解快。本仓库同一道例题五种写法都给了，方便你随时换。
>
> 授权方面：HiGHS 是 MIT，SCIP 从 8.0.3 起是 Apache 2.0，两者都能直接商用。

## 0.2 安装

```bash
# 开源求解器 + 建模层，装完立刻能跑（推荐先做这一步）
pip install highspy pyscipopt pulp pyomo

# 商用求解器按需装
pip install gurobipy      # 装完还要授权，见 0.3
pip install coptpy        # 自带受限试用 license
pip install docplex       # CPLEX 的建模接口，求解还需要 CPLEX 运行时
```

也可以直接用仓库的依赖文件：

```bash
pip install -r requirements.txt
```

## 0.3 授权（商用求解器才需要）

**Gurobi**

```bash
pip install gurobipy
# 到 https://portal.gurobi.com/ 注册（学生/学术免费），拿到 license key 后：
grbgetkey xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

license 文件默认在 `~/gurobi.lic`。过期后所有报错都是 `License expired`，重新 `grbgetkey` 即可。

**COPT**

`pip install coptpy` 自带的试用 license 无需额外配置，直接能用，但求解规模有上限（详见[官网](https://www.shanshu.ai/copt-document/)）。商用请申请正式 license。

**CPLEX**

`docplex` 只是 Python 建模接口，真正求解需要本机有 CPLEX 运行时（Optimization Studio，或免费但有规模上限的社区版）。没有运行时会报 `Cannot solve model: no CPLEX runtime found.`。

没有运行时，哪些事能做、哪些不能：

| 操作 | 需要运行时 |
| :--- | :--- |
| 建模、加约束、加指示约束 | ❌ 不需要 |
| `export_as_lp()` 导出 LP 文本 | ❌ 不需要 |
| `export_as_mps()` 导出 MPS | ✅ 需要（MPS 导出走引擎） |
| `ModelReader().read()` 读模型 | ✅ 需要 |
| `solve()` | ✅ 需要 |

## 0.4 版本与验证

不同版本的求解器 API 会变，本仓库踩过两个真实的：HiGHS 的 Python 接口从「构造矩阵 + `passModel`」改成了 `addVariable` 代数式写法；COPT 的 `addConstr` 第 2 个位置参数是 `sense` 而不是 `name`（这是与 Gurobi 的固有差异，不是版本变化）。详见[第 9 章](./09-常见错误与排查.md)。

本仓库实际验证过的版本：

| 求解器 | 验证版本 |
| :--- | :--- |
| Gurobi | 14.0（API 按官方文档与 type stub 核对；求解需许可证） |
| COPT | 8.0.1 |
| CPLEX / docplex | docplex 2.32（建模语法与 LP 导出已核对，求解需本地 CPLEX 运行时） |
| HiGHS | 1.16.0 |
| SCIP | SCIP 10.0（PySCIPOpt 6.3.0） |
| PuLP | 3.3.1 |
| Pyomo | 6.10.1 |

## 0.5 装完先自检

```bash
python scripts/verify_all.py
```

这个脚本会把仓库里每道例题、每个求解器都跑一遍，并**比对最优目标值是否一致**。输出长这样：

```
汇总（✓ 通过 / - 跳过 / ✗ 失败）
例题                  COPT     CPLEX    Gurobi   HiGHS    PuLP     Pyomo    SCIP
lp_profit           ✓        -        -        ✓        ·        ·        ✓
knapsack            ✓        -        -        ✓        ·        ·        ✓
facility            ✓        -        -        ✓        ·        ·        ✓
scheduling          ✓        -        -        ✓        ·        ·        ✓
cvrp                ✓        ·        -        ✓        ·        ·        ✓
lp_profit(建模层)      ·        ·        ·        ·        ✓        ✓        ·
facility(建模层)       ·        ·        ·        ·        ✓        ✓        ·

全部通过 ✅
```

在这之前还会逐个例题、逐个求解器打印一行明细，最后还有一组「冒烟测试」（第 5、6 章的脚本只写文件、生成日志，跑通即算过）。

- `✓` 通过：跑通且最优值和标准答案一致
- `-` 跳过：本机没装该求解器，或没有有效 license
- `✗` 失败：代码有 bug，或算出来的值和标准答案不一致

**没有 license 不算失败**，有 HiGHS / SCIP 就能把整套例题跑通，这也是 CI 只用开源求解器的原因。
