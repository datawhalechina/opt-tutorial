# 第 4 章 常见建模技巧

会写 API 只是第一步。真正决定模型"能不能解、解得快不快"的是**怎么把业务语言翻译成约束**。这一章讲四个高频技巧。

## 4.1 半连续："要么不生产，要么至少产这么多"

### 问题

2 台机器、3 个产品。机器启用有固定成本；**一旦启用，产量必须落在 $[\text{min\_output},\ \text{capacity}]$ 之间**。

| 机器 | 固定成本 | 产能 | 最小起产量 |
| :---: | ---: | ---: | ---: |
| 1 | 10 | 20 | 8 |
| 2 | 10 | 20 | 8 |

单位成本：

| 机器 \ 产品 | P1 | P2 | P3 |
| :--- | ---: | ---: | ---: |
| 1 | 5 | 1 | 5 |
| 2 | 1 | 5 | 1 |

需求：P1 = 4、P2 = 10、P3 = 4。

最优解：两台机器都开，机器 1 只做 P2（10 件），机器 2 做 P1 + P3（正好 8 件，卡在下限上），总成本 **38**。

### 两种等价写法

设 $y_i \in \{0,1\}$ 表示是否启用，$p_{ik}$ 是产量，$s_i = \sum_k p_{ik}$ 是机器总产量。

**写法 A：指示约束**（"如果 $y_i = 1$，则 $s_i \ge 8$"）

**写法 B：两条 big-M 线性约束**

$$
s_i \ge \text{min\_output}_i \cdot y_i, \qquad s_i \le \text{capacity}_i \cdot y_i
$$

$y_i = 0$ 时两条夹住 $s_i = 0$；$y_i = 1$ 时退化成 $[\text{min\_output}, \text{capacity}]$。**完全等价，且不依赖任何高级约束**。

### Gurobi：指示约束

```python
model.addGenConstrIndicator(y[i], 1, total_production_i >= min_output[i], name=f"min{i}")
```

前两个参数是"哪个 0-1 变量、取什么值"，第三个参数是取该值时必须成立的约束。

### COPT：指示约束

```python
model.addGenConstrIndicator(
    y[i], 1,                              # 0-1 变量、取值
    total_production_i,                   # lhs
    COPT.GREATER_EQUAL, min_output[i],    # sense、rhs
    name=f"min{i}",
)
```

签名是 `(binvar, binval, lhs, sense, rhs, type=1, name="")`，比 Gurobi 多一层拆分。

### CPLEX：指示约束

```python
model.add_indicator(y[i], model.sum(p[i, k] for k in range(3)) >= min_output[i],
                    active_value=1, name=f"min{i}")
```

### SCIP：指示约束

```python
model.addConsIndicator(total_production_i >= min_output[i], binvar=y[i], activeone=True,
                       name=f"min{i}")
```

### HiGHS：只能用 big-M

**HiGHS 不支持指示约束**，必须写成两条线性约束：

```python
model.addConstr(s_i - capacity[i] * y[i] <= 0, f"capacity{i}")
model.addConstr(s_i - min_output[i] * y[i] >= 0, f"min_output{i}")
```

这就是为什么不建议一上来就用指示约束：**换求解器时会不兼容**。写法 B（big-M）通用性最好，代价是要求你自己把 $M$ 取紧。

| 求解器 | 指示约束 | big-M |
| :--- | :---: | :---: |
| Gurobi | ✅ | ✅ |
| COPT | ✅ | ✅ |
| CPLEX | ✅ | ✅ |
| SCIP | ✅ | ✅ |
| HiGHS | ❌ | ✅ |
| PuLP / Pyomo | 取决于后端 | ✅ |

## 4.2 逻辑约束三件套

设 $x, y \in \{0,1\}$：

| 业务语言 | 线性写法 |
| :--- | :--- |
| $x$ 和 $y$ 至少选一个（或） | $x + y \ge 1$ |
| $x$ 和 $y$ 不能同时选（互斥） | $x + y \le 1$ |
| 选了 $x$ 才能选 $y$（如果 $x$ 那么 $y$） | $x \le y$ |
| $x$ 与 $y$ 必须一致 | $x = y$ |
| 最多选 $k$ 个 | $\sum_i x_i \le k$ |
| 恰好选 $k$ 个 | $\sum_i x_i = k$ |

这些写法都不需要指示约束，优先用它们。

## 4.3 对称性破除

如果有 $k$ 台完全相同的机器，解 $\{1,2\}$ 和 $\{2,1\}$ 本质是同一个，但求解器会当成两个不同的分支去搜，浪费时间。

常见写法：**按编号强制排序**

$$
y_1 \ge y_2 \ge \cdots \ge y_k \quad\Longleftrightarrow\quad y_{i+1} \le y_i
$$

或者在对称的组内只允许"先开小编号"：$y_i \le \sum_{l<i} y_l$。

规模不大时感觉不出来，节点数上到十万级时能差一个数量级。

## 4.4 数值稳定性

求解器默认的可行性容差是 $10^{-6}$ 量级。以下写法容易翻车：

| 坏习惯 | 后果 | 建议 |
| :--- | :--- | :--- |
| big-M 填 `1e10` | LP 松弛极弱，分支爆炸；不同求解器结果不一致 | 用问题自身的上界 |
| 系数跨度 $10^9$ | 单纯形数值失败、警告 `numerical trouble` | 统一量纲（元→万元、克→吨） |
| 用 `==` 表示"差不多等于" | 永远不可行 | 改成区间约束 `a <= expr <= b` |
| 0-1 变量写成 `x <= 0.999` | 整数判定失败 | 用真正的 binary 类型 |
